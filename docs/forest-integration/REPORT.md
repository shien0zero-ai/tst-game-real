# 銃と森林の整合・画質維持の性能検証（2026-11-17）

ユーザー指定を維持：1920×1080、内部解像度100%、Cinematic（sg.*=4）。Lumenのサンプル数、描画距離、霧、植生密度、森林の照明と素材を下げていません。既存Godot・Depot 04・M1911・過去の銃/手・配布版・セーブを保持。追加インストールとエンジン変更なし。

## 修正と根拠

旧FieldFinishの3メッシュはrecompute_normals=Trueだったため、原本のスムーズ法線を保存する別資産Integrationを作成。分割頂点の再計算が曲面の見え方を損なう経路を修正しました。元のGLBには平面法線と異なる法線があり、旧設定が元の法線を使用していないことは確認済み。画面上の差すべてをこの一点だけに帰属させるものではありません。

新資産はrecompute_normals=False、tangent再計算、高精度tangent、full precision UVs。元4Kカラー/法線/ARMを維持し、固定色に近かったグリップを原本の色・凹凸へ戻しました。金属・非金属・ゴム・操作部で反射と粗さを分け、エッジ摩耗は0.10〜0.25mmの細い範囲に抑えています。元のテクスチャは正しくsRGB/Normalmap/Masksに設定済みで、ガンマ誤設定の修正ではありません。

革手袋は別マテリアルで明るさ・粗さ・法線の強さを調整。銃と両手は同一のlighting attachment groupとし、接触部の陰影を一体として処理します。形状、握り位置、専用指アニメーションは今回新しく作り直していません。銃身/銃口を含む旧形状・M1911と従来の保持姿勢は保存。森林へ専用の補助光を追加していません。

同一カメラ・検品姿勢、1920×1080の比較：[修正前](before.png) / [修正後](after.png)。森の設定は同じ。20秒後の静止画で、通常のFPS評価には使用しません。キャプチャ専用フラグでHUDを隠しています。

## 性能

RTX 5080 / Ryzen 9 9950X3D / 約32GB RAM、UE5.8.4 Development D3D12。通常のゲームウィンドウを表示・フォーカスして単独で実行。各条件は3区間（小径の歩行・林内の見回し・別の小径）、各10秒ウォームアップ後25秒を実時間で記録。起動/準備区間を除外し、測定区間のヒッチは除外しません。Editor、Cook、スクリーンショットを並行実行していません。VSync/FPS上限なし。全マップの最低値やユーザーの入力遅延を保証する測定ではありません。

| 条件 | 平均FPS | 1% Low | GPU平均ms |
|---|---:|---:|---:|
| 旧配布版 | 41.48 | 35.05 | 23.57 |
| 修正版・標準32スレッド群 | 41.69 | 35.04 | 23.42 |
| 標準32再測定 | 49.96 | 41.33 | 19.54 |
| 旧配布版再測定 | 50.77 | 45.13 | 19.22 |

64スレッド群の候補はWindowsパッケージでGPUクラッシュ（DXGI_ERROR_DEVICE_HUNG）が発生したため非採用。測定不成立でFPS値はありません。既定32スレッド群を維持。クラッシュの内部原因は未確定で、ドライバー/エンジンのどちらかに断定していません。

採用経路の2回・計150秒の測定を合算した平均は **45.82FPS**。100・80・60FPSの目標はいずれも未達です。画質低下で目標を達成した扱いにはしていません。実行間の数値に変動があるため各回を併記し、銃修正による明確なFPS改善は確認できていないと評価します。

詳細GPUイベントツリー（旧設定の開始位置、単一フレームの診断値）：Frame Time19.79ms、async側LumenScreenProbeGather13.02ms（うちComputeLightingPDF3.07ms、TraceGlobalSDFAndApplyRadianceCache3.64ms）、graphics側ShadowProjectionOnOpaque2.89ms、VolumetricFog1.81ms。非同期処理が重なるため、これらを足して総フレーム時間にしてはいけません。間接光の品質維持が主な性能制約で、銃の頂点削減だけでは60FPSを保証できません。

実行構成の単一フレーム予備比較：既定19.79ms、Lumen async無効20.47ms、64スレッド群18.50ms、反射/TSRのasync拡張21.07ms。これは候補選定用で、64スレッド群はパッケージ版で安定性検証に失敗したため、Editorでの速い単一フレームを採用理由にしていません。Lumenサンプル削減・解像度低下は試していません。

## 動作確認と限界

Win64 Development Editor成功、実PIE worldtype=3とWindows配布版worldtype=1はいずれも30 PASS / 0 FAIL。射撃、リロード、ADS、移動、F2、F3でM1911と残弾保持、FPS表示、音源23個、手の完全形状、新UV/tangent精度、影の接続を検証。MSVC14.52.37029 / Windows SDK10.0.26100.0。既知のEditor AutomationTest Condition failed19件およびMSVC推奨版警告は抑制していません。Editor起動時の既知ログは解明済みという意味ではありません。最終ZIPは新規フォルダーに全展開して13入力項目を確認する公開ゲートを維持。

銃声は前版の実録音・反響/遮蔽処理を維持。本作は試作であり、銃/手の高密度な造形と専用アニメーション、森林光の測光校正、より多様な樹形には限界が残ります。設定だけで商用FPS並みのモデル品質へ到達したとは報告しません。

## 再現

EditorでTools/import_integration.pyを実行し、Tools/audit_integration.pyで新旧のビルド設定を確認。Tools/build_forest.ps1のEditor/PIE/Windows/Verifyを順に実行。性能測定はTools/benchmark_visible.ps1 -Name <比較名>、非採用の64スレッド群はGPUクラッシュしたため通常起動には適用しません。比較旧版は-Executableで保存済み配布版を指定。測定中は他のUEプロセスと入力を避けます。生CSV/JSONと資産監査JSONをこのフォルダーへ保存しています。
