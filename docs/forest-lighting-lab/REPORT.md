# 森林照明の比較試作（2026-11-19）

元の`unreal/AshgateForest`と過去の配布版・セーブを保持し、`unreal/AshgateForestLightingLab`に独立した64×64m区画を作成しました。追加インストール、エンジン変更、警告の抑制は行っていません。

## 実測結果

RTX 5080、1920×1080、Cinematic、内部解像度100%、フレーム生成なし。Lumenと事前計算の小区画は同じ地形・配置・素材・カメラ・3ルートです。各ルート10秒の準備後に25秒測定。小区画は各2回、既存配布版と全森林の再現版は各1回測定しました。0.25〜0.5秒間隔で前面表示を確認し、測定区間での喪失を検出した回は除外しました。撮影・照明計算・Cookは同時実行していません。

| 比較条件 | 平均FPS | 1% low | GPU平均ms |
|---|---:|---:|---:|
| 既存配布版・従来ルート | 52.90 | 46.90 | 18.36 |
| 既存の森を再現・共通ルート | 51.58 | 44.83 | 18.85 |
| 64m小区画・Lumen | 68.79 | 57.89 | 14.03 |
| 同じ64m小区画・事前計算 | 145.82 | 117.53 | 6.34 |

同一小区画での平均FPS比は2.12倍です。元の配布実行ファイルは従来の全森林ルートを使用します。再現版は小区画と同じルートで全森林を描画します。小区画化の効果と照明・反射方式の効果を混同しないでください。この結果は全256m森林を事前計算した場合の100FPSを保証しません。

詳細な各回・フレーム時間・GPU時間は[performance.json](performance.json)とCSVに保存しています。平均FPSは全フレーム数／実測秒数、1% lowは最も遅い1%のフレーム時間の平均から算出しています。

## 実装

地面は元と同じ1m格子・高さ関数・地表マテリアルに、専用のライトマップUVを追加しました。同じ保存マップを使う小区画のLumen／事前計算の配置CRC32はともに`671F7B75`、5972インスタンスです。地形・植生を簡素な代替モデルへ置き換えていません。全森林の再生成版では近傍の件数は同じですがCRCが異なりました。保存マップと実行時生成の回転・スケール等の差の詳細原因は未確定で、全森林の再生成版は厳密な同一配置比較ではなく参考値として扱います。

CPU LightmassのProduction設定で間接光を計算し、表面マッピング24件・11クラスタと、空間照明のデータを保存しました。93,042,090バイトのネイティブ照明データは可逆圧縮し、分割ファイルと最終SHA-256を照合して復元できます。元の素材は不足分のみ別プロジェクトへコピーし、元ファイルを上書きしません。

太陽の間接光を事前計算し、実行時の直接光と影は動的に扱います。銃・手はMovableのまま空間照明を受け、動的・接触影を維持します。反射はLumenからSSR＋森林の反射キャプチャへ変えるため、計測差はGIだけではなく照明・反射方式全体の差です。

Nanite植生との互換性を保つためVSMを維持し、遠方の動的な影も残しています。近距離だけの動的な影に限定した最終方式ではありません。[EpicのVSM仕様](https://dev.epicgames.com/documentation/en-us/unreal-engine/virtual-shadow-maps-in-unreal-engine)に従い、静的な遠景の影まで全面的に置換した方式とは区別しています。

## 比較画像と見た目

近距離の地表の凹凸、シダ・下草、木の形と配置、細かな木陰は維持できています。事前計算版はLumen版より銃の金属が暗く暖色寄りになり、植生の陰の明るさにも差があります。反射方式と間接光の違いが残るため、「完全に同じ見た目」とは評価していません。小区画の外には遠景を配置していないため、奥の地形と森林は途切れます。

起動直後のVSMキャッシュで大きく粗い影が残る問題を確認しました。影自体を無効にせず、開始8秒間はキャッシュを更新し続け、その後は通常のキャッシュを有効にする処理で比較画像の症状が解消しました。エンジン内部の詳細な発生条件は未確定です。性能測定はキャッシュが有効に戻った後に実施します。

## 検証と制限

Editorビルド成功、実PIE 34 PASS、Windows版 34 PASS、0 FAIL。Windowsで歩行、ADS、発砲、空撃ち、装填、F3のM1911、銃の表示切り替え、メニュー、終了確認の13状態を確認しました。公開ツールは作成したZIPを別フォルダーへ展開し、同じ入力検証を通した場合だけ公開します。

保存済みの表面光とVLMを別プロセスから読み込んで検査しました。GPUプロファイルではLumen版のScreenProbeGatherを確認し、事前計算版では同パスがないことを確認しました。MSVC 14.52.37029 / Windows SDK 10.0.26100.0。

植生の元UVには重複が残り、Lightmassの警告を[bake-uv-warnings.txt](bake-uv-warnings.txt)へ保存しています。植生には表面ライトマップではなくVLMを用い、細かな直射影は動的に描画します。既知のEditor起動AutomationTestのCondition failedおよびコンパイラー警告を抑制していません。初回の無人保存で照明ファイルが残らない不具合は保存APIとファイル検証を修正し、再計算後の別プロセス検証で解消を確認しました。

音とM1911は元の版を保持。P38の録音とSoundWaveは単体公開せず、ライセンスで許可された完成ゲームへの組み込みだけを配布します。
