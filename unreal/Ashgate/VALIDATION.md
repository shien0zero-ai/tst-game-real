## Windowsゲームの入力経路

配布用ゲームを起動し、対象ウィンドウへWindowsのキーイベントとマウスクリックを送りました。テスト用F9で状態と実画面を記録し、次の14時点をログで確認しました。通常プレイではF9検証機能は有効になりません。

|---|---|
| 拠点の射撃場をマウスでクリック | base → raid |
| Wを1秒押す | X=-3900/Y=-3300 → X=-3638.261/Y=-3109.835、約3.24m移動 |
| N | inspect=3.94秒 |
| 右クリック | aiming=1、inspect=0 |
| 左クリック | ammo=7 → 6 |
| R / 待機 | reload=1.10 → 完了、ammo=7 |
| Tab | bag=1、paused=0 |
| Esc | bag=0、paused=0 |

ゲームは終了コード0で終了しました。検証はQA用スロットだけを使い、カーソル位置と元の前面ウィンドウを戻しました。人間による長時間の手動プレイは未実施です。

## r2: ボタン操作後の終了報告への対応

利用者の展開先ログにはREADYの後、Closing by requestとUGameEngine::HandleExitCommandがあり、例外・Fatal errorはありませんでした。正確な終了要求の発生元は旧版では記録不足のため未確定です。別の通常起動コピーでは出撃して動作し、無操作での異常終了は再現していません。

メニュー入力を武器の押下処理と座標の行番号計算から切り離し、描画したUE標準HUDヒットボックスと押下・解放の一致で判定します。終了は確認画面で明示的に選択した場合だけ実行し、選択ボタン名をMENUログへ残します。Editorビルド、Windowsパッケージ、PIEと配布版の29項目の回帰検証、およびメニュー入力と終了キャンセルを検証しました。

配布ZIPを新規フォルダーへ実際に展開し、直下Ashgate.exeから通常保存スロットAshgateUE5_Profile_v1で検証しました。既定の全画面（このPCでは1920x1080）で実際の出撃、1600x900のウィンドウで射撃場をそれぞれ開始し、移動・武器操作・バッグ・Esc・感度・帰還・終了確認・キャンセル・明示的な終了まで、各16時点の状態を検証スクリプトで照合しました。両方でINPUT VALIDATION PASS、確認後の終了とログのクローズを確認しています。-AshgateInputCaptureはF9記録のみで、QA用の初期化や自動終了は行いません。既存の利用者フォルダーとセーブは変更していません。詳細は[入力検証抜粋](../../docs/ue5-r2-menu-validation.txt)にあります。
